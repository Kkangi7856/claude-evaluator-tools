# Qualitative Outcome — 보도자료 → 정성성과 정리

## 개요

보도자료 파일을 받아 **「정성성과 양식」(2열 6행 표)의 각 항목에 맞춰 성과를 정리**한
한글 문서를 생성한다.

| 행 | 항목 | 내용 |
|---|---|---|
| 1 | 성과명9) | 보도자료 제목(+ 부제) |
| 2 | 관련 사업 (과제) | 사업명 / 과제명(과제번호) / 수행기관·연구책임자 / 총 연구기간 / 총 연구비 |
| 3 | 추진배경 | 연구가 왜 필요했는지 — 배경·문제의식·한계 |
| 4 | 추진내용 | 실제로 무엇을 수행했는지 — 방법·접근 |
| 5 | 추진성과 | 무엇을 규명·확보했는지 + 게재 학술지 + 기대효과 (+ 그림·캡션) |
| 6 | 비고 | 관련기사 제목(언론사, 날짜) / 기사 링크 |

## 절대 규칙 — 사실성

1. **보도자료에 적힌 내용만으로 작성한다.** 외부 지식·추정·일반 상식을 끌어와 채우지 않는다.
2. **없는 정보는 만들어 내지 않고 공란으로 둔다.** 특히 다음은 보도자료에 명시되지 않으면 비운다.
   - 과제명·과제번호(RS-…), 수행기관/연구책임자명, 총 연구기간, 총 연구비
   - 관련기사 제목·언론사·날짜·기사 링크(URL)
   - 그림(보도자료에 삽입 이미지가 없을 때)
   공란은 사용자가 직접 채워 넣는다. 라벨만 남기고 값은 비워 두면 된다(예: `  - 총 연구비: `).
3. 표현·문장 구조는 공문 문체로 다듬어도 되지만, **사실·수치·고유명사는 원문 그대로** 유지한다.
   - 날짜/수치/학술지명/기관명/인명을 바꾸거나 보완 추정하지 않는다.
4. 확신이 서지 않는 항목은 채우지 말고 비운다. **비우는 것이 틀리게 쓰는 것보다 낫다.**

## 작업 절차

### 1단계 — 보도자료 추출
```
python "${CLAUDE_PLUGIN_ROOT}/skills/qualitative-outcome/scripts/extract_press.py" "보도자료.hwp" --images-dir "_press_images" --json "press.json"
```
- 지원 형식: `.hwp`(바이너리), `.hwpx`, `.txt`, `.md`
- 출력: `{ "text": 본문, "images": [{path, width, height}], "links": [URL…] }`
- `links` 가 비어 있으면 **비고의 기사 링크는 공란**이다.
- `images` 가 비어 있으면 **그림은 삽입하지 않는다**.

### 2단계 — 항목별 재구성 (Claude 가 수행)
추출된 본문을 읽고 각 항목을 아래 대응 관계로 채운다.

| 양식 항목 | 보도자료에서 주로 가져오는 부분 |
|---|---|
| 성과명 | 맨 앞 제목 줄 + `- … -` 부제 |
| 관련 사업 (과제) | "○○사업의 지원으로 수행" 문장에서 **사업명만** 확인 가능한 경우가 많다 |
| 추진배경 | `1. 연구의 필요성`, 도입부 `□` 문단 |
| 추진내용 | `2. 연구내용` |
| 추진성과 | `3. 연구성과/기대효과` + 게재 학술지·게재일 |
| 비고 | 본문에 있는 기사 링크·언론 보도 정보(없으면 공란) |

문체 규칙은 `references/writing-guide.md` 참조. 요약하면:
- 1단계 `□ 개조식 요지` → 2단계 ` ○ 세부` → 3단계 `   - 근거·부연` 의 계층
- 추진성과 첫 줄은 `□ 핵심 규명 내용`, 그 다음 줄에 `➔ 국제학술지 …에 게재(YYYY.M.D.)`
- 각 줄은 명사형(`~ 규명`, `~ 확보`, `~ 제시`)으로 끝맺는다.
- 줄머리 기호 앞뒤 공백(` ○ `, `   - `)은 그대로 두면 렌더러가 내어쓰기를 맞춰 준다.

### 3단계 — 스펙(JSON) 작성
`outcome_spec.json` 을 아래 스키마로 작성한다.

```json
{
  "out_name": "정성성과.hwpx",
  "fields": {
    "성과명":           ["제목", "- 부제 -"],
    "관련 사업 (과제)": ["□ 사업명: …", " ○ 과제명: ", "  - 수행기관/연구책임자명: "],
    "추진배경":         ["□ …", " ○ …", "   - …"],
    "추진내용":         ["□ …", "   - …"],
    "추진성과":         ["□ …", "➔ …", " ㅇ …", "   - …"],
    "비고":             []
  },
  "image": {
    "path": "_press_images/press_image1.bmp",
    "caption": "< 그림 설명 >"
  }
}
```

| 키 | 설명 |
|---|---|
| `out_name` | 출력 파일명(기본 `정성성과.hwpx`) |
| `fields` | 항목명 → **줄 배열**. 빈 배열이면 그 칸은 공란 |
| `image` | 선택. 보도자료에 그림이 있을 때만 지정. `추진성과` 칸 끝에 그림 + 캡션 삽입 |
| `image.caption` | 보도자료의 `(그림1) …` 설명을 `< … >` 로 감싸 사용. 없으면 생략 |

전체 예시는 `references/sample-spec.json` 참조.

### 4단계 — 문서 생성
```
python "${CLAUDE_PLUGIN_ROOT}/skills/qualitative-outcome/scripts/render_outcome.py" --spec "outcome_spec.json" --outdir "."
```
- 결과: `정성성과.hwpx` (한글에서 바로 열림)
- `--to-hwp` 를 붙이면 한컴오피스로 `.hwp` / `.pdf` 도 생성(한컴오피스 설치 필요)
- 사용자가 별도 양식을 주면 `--template "정성성과 양식.hwpx"` 로 지정
- Windows PowerShell 에서는 한 줄로 실행한다.

### 5단계 — 결과 보고
생성 파일 경로와 함께 **공란으로 남긴 항목을 반드시 명시**한다.
예: "과제명·수행기관·연구기간·연구비, 관련기사·기사 링크는 보도자료에 없어 공란으로 두었습니다."

## 의존성
- Python 3.8+ — 표준 라이브러리만으로 `.hwpx` 생성 가능
- `olefile` — 바이너리 `.hwp` 읽기 (`pip install olefile`)
- `pillow` — 그림 크기 산출 (`pip install pillow`), 없으면 기본 크기 사용
- `pyhwpx` + 한컴오피스 — `--to-hwp` 사용 시에만 필요

## 구현 메모(중요)
- 렌더러는 번들된 양식 `assets/outcome-template.hwpx` 의 **표 2열(내용 칸)만 교체**한다.
  라벨·테두리·여백 등 서식은 원본 양식 그대로 유지된다.
- 줄머리 기호(`□ ○ ㅇ - ※ * ➔`)를 감지해 `paraPr` 을 복제·생성하고 내어쓰기(`intent`)를
  자동 계산한다. **`header.xml` 의 `<hh:paraProperties itemCnt>` 도 함께 갱신해야**
  한글이 새 `paraPr` 을 인식한다.
- 그림은 `BinData/image1.<ext>` 로 zip 에 넣고 `Contents/content.hpf` 의 `<opf:manifest>` 에
  `isEmbeded="1"` 항목을 추가한 뒤, 문단 안에 `treatAsChar="1"` 인 `<hp:pic>` 로 삽입한다.
  크기는 96dpi 기준 `픽셀 × 75` HWPUNIT 로 환산하고 칸 너비를 넘지 않게 축소한다.
- 표 행 높이는 한글이 문서를 열 때 자동으로 재계산하므로 별도 조정하지 않는다.
