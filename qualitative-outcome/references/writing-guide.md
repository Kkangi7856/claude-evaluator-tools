# 정성성과 작성 가이드

「정성성과 양식」 각 칸을 채울 때의 문체·계층·사실성 규칙.

## 0. 대전제 — 보도자료 밖으로 나가지 않는다

- 보도자료 본문에 **명시된 내용만** 쓴다. 배경지식으로 보충하지 않는다.
- 숫자·날짜·기관명·인명·학술지명·과제번호는 **원문 그대로**. 반올림·추정·보정 금지.
- 확인되지 않는 항목은 **공란**. 라벨만 남기고 값은 비운다.
  ```
   ○ 과제명:
    - 수행기관/연구책임자명:
  ```
- "~로 보인다", "~일 것으로 추정된다" 같은 추측 표현을 쓰지 않는다.

## 1. 계층 구조

```
□ 큰 덩어리 요지 (1단계)
 ○ 세부 논점 (2단계)
   - 근거·부연·구체 내용 (3단계)
```
- 기호 앞의 공백은 그대로 유지한다(` ○ `, `   - `). 렌더러가 이 공백 폭만큼
  내어쓰기를 잡아 줄바꿈 시 정렬을 맞춘다.
- 추진성과 칸에서는 2단계에 `○` 대신 `ㅇ` 를 쓰는 관행이 있다(양식 예시 기준).

## 2. 항목별 작성 요령

### 성과명
- 보도자료 제목을 그대로 첫 줄에 쓴다.
- 부제가 있으면 둘째 줄에 `- 부제 -` 형태로 그대로 옮긴다.

### 관련 사업 (과제)
```
□ 사업명: (보도자료에 명시된 사업명)
 ○ 과제명: (없으면 공란)
  - 수행기관/연구책임자명: (없으면 공란)
  - 총 연구기간: (없으면 공란)
  - 총 연구비: (없으면 공란)
```
- 보도자료는 보통 "○○사업의 지원으로 수행됐다" 정도만 밝히므로 **사업명만 채워지고
  나머지는 공란인 경우가 정상**이다.
- 보도자료에 여러 연구자·기관이 나오더라도, "연구책임자"라고 명시돼 있지 않으면
  수행기관/연구책임자 칸을 채우지 않는다.

### 추진배경
- 「연구의 필요성」 및 도입부에서 **왜 이 연구가 필요했는지**를 뽑는다.
- 보통 두 덩어리: ① 기술의 중요성·필요성 증대 ② 기존 방식의 한계·미해결 쟁점.
- 성과(결과)를 여기에 쓰지 않는다.

### 추진내용
- 「연구내용」에서 **무엇을 어떻게 수행했는지**(방법·실험·분석)를 뽑는다.
- 결과·의의는 추진성과로 넘긴다.

### 추진성과
- 첫 줄: `□ (핵심적으로 규명·확보한 것)`
- 둘째 줄: `➔ 국제학술지 OOO(원어명, Impact Factor = N)에 게재(YYYY.M.D.)`
  - Impact Factor 는 보도자료에 있을 때만 쓴다.
  - 게재일이 "7월 6일"처럼만 나오면 보도자료의 발행 연도를 근거로 `2026.7.6.` 형식으로
    옮긴다. 연도를 알 수 없으면 원문 표기를 유지한다.
- 이후 ` ㅇ 성과 묶음` → `   - 구체 근거` 로 2~3개 묶음을 만든다.
- 마지막 묶음은 보통 **기대효과·확장 가능성**이다.
- 그림이 있으면 표의 이 칸 끝에 그림과 캡션이 들어간다(렌더러가 처리).

### 비고
```
□ 관련기사: (기사 제목)(언론사, YYYY.M.D.)
 ※ 기사 링크: (URL)
```
- 보도자료에 기사 정보나 URL이 없으면 **칸 전체를 공란**으로 둔다(빈 배열 `[]`).

## 3. 문체

- 개조식·명사형 종결: `~ 규명`, `~ 확보`, `~ 제시`, `~ 입증`, `~ 마련`
- `~했다`, `~합니다` 같은 서술형 종결어미를 쓰지 않는다.
- 한 줄은 대체로 60~110자. 너무 길면 하위 항목으로 쪼갠다.
- 원문의 인터뷰 인용("…라고 밝혔다")은 그대로 옮기지 않고, 사실 부분만 개조식으로 옮긴다.

## 4. 그림·캡션

- 보도자료에 삽입된 이미지가 있으면 추출해 추진성과 칸에 넣는다.
- 캡션은 보도자료의 `(그림1) …` 설명 문구를 `< … >` 로 감싸 쓴다.
- 이미지가 없으면 `image` 키를 아예 넣지 않는다(사용자가 직접 삽입).
